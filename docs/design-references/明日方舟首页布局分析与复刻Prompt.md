## 一、四张图共同的布局

### 1. 全屏画布中的左右分工

四张图都接近 16:9。图 1～3 为 600×338，图 4 为 600×339。它们使用固定构图：背景铺满屏幕，角色占据中左部，主要功能集中在右侧，工具和辅助信息分散在左侧边缘。

下面的百分比是对截图的目测范围，用于描述构图；它们不是游戏源码中的布局参数。

| 区域 | 大致范围 | 布局作用 |
| --- | --- | --- |
| 左上工具区 | 横向 2%～24%，纵向 2%～10% | 一排小工具，不形成横贯全屏的导航栏 |
| 左侧身份区 | 横向 0%～22%，纵向 36%～60% | 等级、身份等信息贴近左边缘，视觉重量低于右侧主入口 |
| 角色展示区 | 主要位于横向 15%～56%，纵向贯穿大半屏幕 | 大面积自由轮廓，可以越过左侧信息区；不装进矩形卡片 |
| 左下说明区 | 横向 2%～34%，纵向 63%～78% | 较宽的低矮文本条，与底部入口形成一组 |
| 左下入口组 | 横向 2%～34%，纵向 77%～96% | 左边一块较大的横向卡，右边上下叠两块小卡 |
| 右上状态区 | 横向 51%～96%，纵向 2%～15% | 状态与时间信息，贴在主入口上方 |
| 右侧主入口组 | 横向 54%～100%，纵向 11%～99% | 四层高密度卡片，占据页面的主要操作区 |

这些区域会在视觉上交叠，不适合直接变成几个互不重叠的百分比列。角色姿态、皮肤装饰和局部面板边界也会变化。

### 2. 右侧的四层卡片

```text
                         右上状态信息

                       ┌─────────────────────────┐
                       │          终端           │  第一层：一张大卡
                       └─────────────────────────┘
                     ┌──────────┐ ┌──────────────┐
                     │   编队   │ │     干员     │  第二层：两张中卡
                     └──────────┘ └──────────────┘
                        ┌────────┬────────────────┐
                        │        │    招募标题    │
                        │采购中心├────────┬───────┤  第三层：不等高的复合分组
                        │        │公开招募│干员寻访│
                        └────────┴────────┴───────┘
                      ┌─────────┐ ┌─────────┐ ┌──────┐
                      │  任务   │ │  基建   │ │ 仓库 │  第四层：两宽一窄
                      └─────────┘ └─────────┘ └──────┘
```

这张线框图只表达分组，不表达透视角度。实际截图的行边缘会倾斜，左右端的高度也不同。

- 第一层“终端”是最大的一张卡，宽度接近整个主入口组，单卡面积明显超过第二层任一卡片。
- 第二层“编队／干员”并排，整体高度较低，宽度不必相等。
- 第三层通常最有色彩辨识度。左侧卡片占满整层高度，右侧先有一条窄标题，再有两个并排入口。这个嵌套结构很重要。
- 第四层是两块较宽的主卡和一块较窄的辅助卡。角标和数字只是叠在卡片上的小信息块，不应该为它们重新划出一排。

各层左边缘有小幅错位：大卡、第二层、彩色分组和底部卡片，并没有严格落在同一条垂直线上。层与层之间也保留了窄缝，让背景穿过。

### 3. 透视的规律

右侧顶部卡片的上边缘向右上方抬起；中部一带较接近水平；底部卡片的上下边缘向右下方展开。大体上，靠屏幕右边缘的端面较高，靠角色的内侧较收敛。

因此，右侧卡片群像一个向外展开的面板。左下卡片组则有相反方向的轻微倾斜：靠屏幕左边缘一侧通常较大，向画面内侧略微收拢。两侧共同给中部角色留下空间。

这只是从截图推断出的视觉关系。四张图不足以确定游戏使用了哪个相机焦距、严格的消失点或实际 3D 参数。网页实现可以直接控制每张卡片的四个角，取得相近的投影效果。

需要同时保留：

- 卡片自身的四边形形状。
- 不同行的倾斜方向变化。
- 相邻卡片沿对应边缘留出的缝隙。
- 文字、图标随所属卡片一起投影的关系。

只对全部卡片加同一个 `rotate()` 或 `skew()`，会丢掉上下层之间的透视差别。只裁切背景、让文字完全保持屏幕正向，也会削弱面板感。

【灰度骨架的外观】

用中性灰背景和少量明暗不同的纯色面板区分区域。正式配色与材质以后决定。保留必要的中文入口名称，使用现有系统字体或项目字体，不下载游戏字体或新增远程字体。

文字在局部卡片坐标内排版，参考卡片边缘留白，不统一套一组网页大按钮的居中样式。无需加入英文副标题、编号、大号装饰数字、进度条或游戏角标。

已有图标可以保留作轻量定位标记；不花时间重新设计图标。已有时钟与播放器内部样式可先保留，只调整它们所在的布局容器。

本轮不新增背景图片、角色立绘、玻璃模糊、粒子、动态光效、轮播横幅、鼠标视差、拖拽揭幕或入场动画。不要从截图中裁切 UI 或角色作为页面素材。

【尺寸适配】

沿用固定画布完整显示策略：
scale = min(有效 CSS 视口宽度 / 1920, 有效 CSS 视口高度 / 1080)

画布始终等比居中。16:9 视口接近填满；超宽视口左右留白；竖屏上下留白。使用实际可用的 CSS 视口尺寸，不依据设备物理像素或固定的 devicePixelRatio 计算布局。

不同分辨率和浏览器缩放下，各卡片之间的相对坐标与投影保持不变。禁止分别拉伸宽高，禁止使用 cover 裁掉边缘入口，禁止在本轮私自切换为手机单列布局。

【交互和可访问性】

检查整个投影卡面可点击，内部透明装饰不拦截输入，卡片之间的缝隙不会触发旁边的链接。父级 overflow 不能裁掉必要的焦点提示。

本轮不要求新增动画。若保留已有 hover 或过渡，不能改变卡片的布局坐标；prefers-reduced-motion 下关闭非必要运动。保留金句在减少动态效果时默认暂停的行为。

## 三、使用时的检查重点

第一轮预览先看轮廓：右侧大卡是否足够大，四层是否清楚，第三层是否保留了嵌套结构，底部是否形成宽窄变化，角色位置是否有足够空间。确认后再看标题大小、边距和灰阶。

如果一开始就靠立绘、背景和发光来接近参考图，很难判断布局本身是否准确。当前文档给出的坐标适合作为第一轮实现的起点；最终应以浏览器里的实际投影为准。
