# 侧栏鼠标曲线设计

## 目标

在全站加入与 `https://kuroha.vip/` 首页观感一致的鼠标尾迹。轨迹只在正文主体高度范围内的左右留白区接收新目标点。顶部 Hero、文章封面、图片灯箱和整个页脚不生成轨迹。左右两侧是独立的输入会话，换侧时从新位置起笔，不用旧节点追逐另一侧目标。

## 参考效果取证

参考站使用全视口 Canvas 2D。效果由 20 条阻尼弹簧链组成，每条链有 50 个节点；绘制时用相邻节点的中点拼接分段二次贝塞尔曲线。参考参数如下：

- `friction = 0.5`
- `dampening = 0.25`
- 沿节点链逐级执行 `spring *= 0.98`
- 线条透明度 `0.25`
- 色相中心 `285°`、振幅 `85°`，约在 `200°` 至 `370°` 之间按正弦规律往返
- 色相名义频率 `0.0015 rad/frame`，按 60 FPS 计算，一个周期约 70 秒
- 线条使用加法混合；旧像素每帧保留约 60%，形成残影

这些参数来自公开页面运行状态和公开加载脚本。实现只复现行为和数值，不复制脚本结构或代码。

## 方案选择

### 方案 A：Canvas 2D + 阻尼弹簧链

这是采用的方案。它与参考站的绘制模型一致，能自然产生滞后、回弹和线束分叉。单个固定全屏 Canvas 不参与布局，`pointer-events: none`，也不会挡住正文交互。

### 方案 B：SVG 路径

SVG 便于检查路径，也能做二次贝塞尔曲线，但 20 条路径、1000 个动态节点和逐帧残影会频繁更新 DOM。实现成本更高，视觉仍难与参考站一致。

### 方案 C：CSS 或 DOM 粒子

这类方案适合点状尾迹，无法稳定复现连续的弹簧线束。若增加大量元素来模拟曲线，性能和维护成本都会变差。

## 页面结构

新增 `CursorTrail.astro`，在 `BaseLayout.astro` 中挂载一个带 `transition:persist` 的全屏 Canvas。层级设为 `10`：轨迹可越过正文，同时低于页头、Sakana、音乐播放器和主题切换遮罩。

全站没有两个固定的 `<aside>`。这里的“两侧边栏”定义为正文主体高度范围内，`.container` 内容带与视口左右边界之间的留白区。页头内部容器的 `data-content-boundary` 标记提供横向 `left/right`。普通页面的唯一 `<main>` 提供纵向 `top/bottom`；文章页没有 `<main>`，由 `.post-grid` 上的 `data-cursor-trail-region` 提供纵向范围。

区域分类返回 `left`、`right` 或 `null`。指针必须同时位于正文主体的纵向范围和内容带外侧。`clientY` 在 main 上方或下方时返回 `null`，因此 Hero、文章封面、WaveDivider 与整个页脚都会被排除。PhotoSwipe 打开后也强制返回 `null`，不在全屏灯箱背后生成轨迹。

Canvas 始终覆盖整个视口。门控只作用于新指针采样，绘制层不加正文遮罩：

- 指针在正文内移动时，不产生新轨迹。
- 同一侧生成的弹簧曲线如果因弯曲或回弹自然伸入正文，仍正常显示。
- 指针离开当前侧栏后，本次输入会话结束。旧像素继续淡出，后续事件不再更新旧目标。
- 指针进入另一侧或离开后重新进入同一侧时，所有节点从新坐标初始化，不绘制两个区域之间的连接线。
- 同一侧可以连续创建多次输入会话。Canvas 同时保留尚未淡出的历史轨迹，不限制每侧只能显示一条。

## 动画与生命周期

运行时使用 `requestAnimationFrame` 和 Canvas 2D。第一次有效的侧栏指针事件会把所有节点初始化到当前坐标，避免从页面原点拉出一条意外直线。随后首节点追逐目标点，后续节点追逐前一节点并继承部分速度。

每次输入会话都有独立的 `TrailState`。离开区域、换侧、取消指针或窗口失焦时，当前会话从 `active` 改为 `retiring`；再次进入时创建新状态，不覆盖旧状态。所有 retiring 会话继续逐帧更新和绘制，直到各自的节点收敛。单个会话收敛后只回收自身，不能清空整张 Canvas。

所有物理会话都回收后，Canvas 继续执行 24 帧 `destination-out` 尾衰减。按每帧保留 60% 计算，最强的 8 位 alpha 也会降到不可见范围，随后才执行一次最终清屏并停止动画。reduced motion、非精细指针、Canvas 被替换或实际位图尺寸变化仍可立即硬重置。Astro 客户端切页复用同一 Canvas 且尺寸未变时，只结束当前输入会话，不清除已有轨迹。

每帧先用 `destination-out` 降低旧像素透明度，再以 `lighter` 混合绘制所有尚未收敛的线束。参考站用深色半透明矩形覆盖自己的背景；本站是透明叠层，改用 `destination-out` 才不会给正文蒙上一层黑色，同时保留同样的指数衰减节奏。色相使用独立的全局时钟，每个渲染帧只推进一次，不能随同时存在的会话数量加速，也不能在新会话开始时跳回初始色。

Canvas 位图按设备像素比缩放，CSS 尺寸保持为视口大小。窗口调整时重新设置尺寸并清屏。Astro 客户端切页后复用同一个 Canvas，初始化函数必须幂等，不能重复注册事件或动画循环。

只有同时满足以下条件时才运行动画：

- `(hover: hover) and (pointer: fine)` 匹配；
- `prefers-reduced-motion: reduce` 不匹配；
- 页面存在内容边界标记和 Canvas。

条件在运行时变化时立即清屏并停止动画；恢复后等待下一次侧栏指针事件。

## 文件边界

- `src/components/CursorTrail.astro`：Canvas 标记和层级样式。
- `src/lib/cursor-trail.ts`：参数、二维区域分类、独立色相时钟、弹簧链状态与单帧更新，保持为可测试的纯逻辑。
- `src/scripts/cursor-trail.ts`：DOM 事件、Canvas 尺寸、绘制循环、媒体查询和 Astro 页面生命周期。
- `src/components/SiteHeader.astro`：给稳定的全站容器增加内容边界标记。
- `src/layouts/PostLayout.astro`：给文章正文网格增加纵向触发区域标记。
- `src/layouts/BaseLayout.astro`：挂载组件并加载运行时脚本。

## 测试与验收

Vitest 覆盖侧栏判定、色相范围与周期、节点初始化和弹簧链更新。Playwright 覆盖真实 Canvas 行为：

- Canvas 固定覆盖视口，且不接收指针事件。
- 指针在正文、Hero、文章封面、页脚或打开的 PhotoSwipe 内移动时，Canvas 保持透明。
- 正文主体高度范围内的左右侧栏会产生非透明像素。
- 左侧直接跳到右侧不会在中间形成连接线；右侧从当地开始新轨迹，左侧旧像素自行淡出。
- 离开侧栏再回到同一侧的远处位置也会重新起笔，不连接两段轨迹。
- 同一侧连续进出三次后，三段残影可同时存在，并分别自然淡出至透明。
- 新会话开始 350ms 后，旧会话仍保持可见；不能只留下接近透明的 1 alpha 像素来通过测试。
- 新建但没有移动的会话收敛时，不得把仍在运行的旧会话或整张 Canvas 一并清除。
- 减少动态效果时不绘制。
- 客户端切页后只有一个 Canvas，且交互仍可用。

现有视觉测试会把鼠标放到 `(0, 0)`，该位置会触发轨迹。截图前改为把鼠标放到正文中心并等待 Canvas 清空，避免无关的基线变化。

完整验证执行 `test:run`、`check`、`build`、`check:site` 和 `test:e2e`。通过浏览器在左右侧栏、正文中心、主题切换、页面切换及减少动态效果下做补充检查。开发预览保持在 `http://127.0.0.1:4321/`。

## 数学名称

单条绘制曲线最准确的名称是“分段二次贝塞尔样条”（piecewise quadratic Bézier spline）。完整效果可称为“阻尼弹簧—质点链驱动的二次贝塞尔样条鼠标尾迹”。它不是抛物线、正弦曲线或 Lissajous 曲线；曲线形状由鼠标轨迹和动态节点共同决定，只有色相随时间按正弦规律变化。
