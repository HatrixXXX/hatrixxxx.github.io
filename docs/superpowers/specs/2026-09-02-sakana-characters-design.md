# 双 Sakana 弹簧角色设计

状态：已批准
日期：2026-09-02

## 目标

在博客所有页面底部放置两个来自 [`itorr/sakana`](https://github.com/itorr/sakana) 的弹簧角色：

- 锦木千束固定在左下角，水平镜像后面朝右；拖动方向与人物偏转方向一致。
- 井上泷奈固定在右下角，保持原图方向并面朝左。
- 两个角色都能独立拖拽，松手后按 Sakana 原有物理效果摆动。

参考站只用于核对尺寸和位置，不复制其代码、文案或个人资产。实现使用 Sakana 包内自带的角色图片和音效。

## 范围

本次改动包括全站组件、客户端初始化、依赖声明、类型声明和相关测试。两个实例都隐藏底座，只保留人物和连接杆。不会加入角色切换、自动甩动、开关按钮、配置面板，也不改主题逻辑、文章正文或页面路由。

Sakana 官方说明，两张角色插画取得的是网页非商业使用授权。本设计以博客保持非商业用途为前提。

## 依赖

安装官方 npm 包 `sakana@1.0.8`，并由 pnpm 更新 `package.json` 与 `pnpm-lock.yaml`。包内包含两张角色图和音效，页面运行时不请求 Sakana CDN。

客户端采用动态导入，在浏览器空闲时再加载 Sakana。这样不会让角色脚本阻塞主要内容。浏览器没有 `requestIdleCallback` 时，延时 200ms 后加载。

发布目录包含 `third-party-notices.txt`。该文件原样保留 Sakana 随包 MIT LICENSE 的版权和许可文本，并记录 npm 元数据误标 ISC 的冲突、项目来源、画师来源和插画仅限非商业网页使用的条件。`check:site` 必须校验这份文件存在。

## 组件与挂载

新增 `src/components/SakanaCharacters.astro`，由 `src/layouts/BaseLayout.astro` 挂载一次。组件放在页脚之后、主题过渡层之前，与现有搜索层和音乐播放器保持独立。

组件包含一个装饰层和两个固定定位的锚点。每个锚点内部有独立的 `.sakana-box`，分别传给 `Sakana.init()`。装饰层使用 `transition:persist="sakana-characters"`，Astro 客户端导航时沿用原节点和实例，避免重复创建动画循环。

初始化逻辑放在 `src/scripts/sakana.ts`，从 `BaseLayout.astro` 的公共脚本入口导入。`src/types/sakana.d.ts` 只声明实际使用的构造选项和实例方法，不扩展上游 API。

## 角色配置

两个实例使用同一组基础配置：

```ts
{
  r: 0,
  y: 0,
  scale: 1,
  canSwitchCharacter: false
}
```

左侧实例的 `character` 为 `chisato`，右侧为 `takina`。缩放交给外层 CSS，避免窗口尺寸变化时销毁并重建实例。初始化后通过 `getValue()` 把两个实例的 `r`、`y`、`t`、`w` 归零，主动在 canvas 上绘制一次竖直连接杆，再暂停实例并标记就绪。页面初始姿态静止且杆可见；第一次拖拽松手时由 Sakana 原有事件处理重新启动弹簧。

全局音效保持开启，与参考站一致。底座不能切换角色，因此千束和泷奈不会交换位置。

## 位置与响应式

Sakana 原始画布占用 `500 × 800px`。两个锚点贴住视口底部，桌面和平板缩放为 `0.5`，实际占用约 `250 × 400px`。宽度不超过 480px 时缩放为 `0.32`，实际占用约 `160 × 256px`，两人仍同时显示。

左侧锚点在桌面和平板向视口外偏移 `50px`，手机端偏移 `32px`。这两个数值等于人物在对应缩放下的左侧留白，因此主体刚好贴住视口左边，不会被裁掉，也能减少对正文的遮挡。右侧锚点继续贴右。

左侧只镜像千束的背景位图，不翻转承载 Sakana 动态 `rotate()` 的元素。这样人物面朝右，同时保留原有的交互坐标：鼠标向右拖，人物也向右偏。泷奈的位图和物理变换都不镜像。两个 `.sakana-bed` 使用 CSS 隐藏，画布中的连接杆保留。

角色层使用 `z-index: 15`，低于站点导航、搜索框、音乐播放器和主题全屏动效。透明区域不接收指针事件，Sakana 自身的角色区域仍可拖拽。

## Astro 导航生命周期

脚本在首次 `astro:page-load` 时查找持久化装饰层，并用数据属性防止重复初始化。动态导入完成后分别创建两个实例，再标记组件就绪。Sakana 在导入时向 `<head>` 注入角色尺寸和背景图样式；脚本保存这个 style 节点的引用并加上 `data-sakana-runtime-style` 标记。

客户端导航时，持久化节点和两个实例继续存在。Astro 更换 `<head>` 时会移除运行时注入的样式，因此脚本监听 `astro:after-swap`；若保存的 style 节点已经断开，就把同一个节点重新挂回新页面的 `<head>`。新的页面脚本即使再次触发初始化，也会因就绪标记直接返回。整页刷新由浏览器释放旧实例，不需要额外清理。

如果动态导入失败，脚本记录错误并让空锚点保持不可交互；正文、导航和其他组件继续工作。

## 无障碍与减少动态效果

整个角色层标记为 `aria-hidden="true"`，不加入可聚焦控件，不改变键盘 Tab 顺序。拖拽属于鼠标和触摸设备上的装饰性交互。

在 `prefers-reduced-motion: reduce` 下仍渲染两名角色，但初始化后立即暂停实例，并关闭角色的指针事件。用户能看到静态角色，不会因拖拽或初始状态产生 JavaScript 动画。音效也保持静音。

## 测试

扩展 Playwright 测试，覆盖以下行为：

- 全站布局只生成一个 Sakana 装饰层，内部有两个已初始化实例。
- 首次拖动前两个 canvas 都包含非透明像素，无位移点击不会启动默认姿态。
- 左侧角色为 `chisato`，只有人物位图水平镜像；右侧为 `takina` 且没有镜像。
- 桌面、平板和手机尺寸下，两个角色都贴住对应角落，视口没有水平溢出。
- 两个底座不可见，连接杆和人物仍正常显示。
- 向右拖动千束时，人物视觉中心向右移动；拖拽一个角色只改变该实例，松手后出现摆动。
- 拖动泷奈时千束保持不变；普通模式下满足泷奈触发条件的拖动会调用内嵌语音播放。
- Astro 客户端导航后沿用同一个装饰层，实例数量仍为两个。
- 首页进入文章页、再从文章页返回首页时，两个角色始终可见，Sakana 运行时样式只有一份。
- 减少动态效果模式下角色保持静止且不可拖拽。
- 主题过渡层、搜索框、导航和音乐播放器的层级高于角色。

视觉截图等待组件进入就绪状态后再采集。由于角色出现在所有页面，需要检查并更新现有 21 张 Windows 基线；初始姿态固定为零，截图中不会出现随机摆动。

## 验收标准

- 所有公开页面都显示两个角色，千束位于左下且面朝右，泷奈位于右下且面朝左。
- 两个角色均可独立拖拽，千束的偏转方向与拖动方向一致。
- 两个底座不可见，只保留连接杆和人物。
- 千束主体贴近视口左边，桌面和平板左移 `50px`，手机端左移 `32px`。
- 手机端保留两人并缩小，正文可以正常滚动和点击，页面不产生横向滚动。
- 客户端页面切换不会生成重复角色或重复动画。
- 首页、文章内容页以及客户端返回后的首页都持续显示两个角色。
- 减少动态效果模式只显示静态角色。
- Sakana 资源随站点构建发布，不依赖运行时 CDN。
- 构建产物包含 Sakana 第三方许可和素材来源告知，站点保持非商业用途。
- 单元测试、Astro 类型检查、图片检查、构建产物检查和 Playwright 测试通过。
