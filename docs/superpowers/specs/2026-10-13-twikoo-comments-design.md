# Twikoo 评论切换设计

## 目标与范围

把文章页和 `/guestbook/` 的 Giscus 换成 Twikoo。文章继续按 `/posts/<legacySlug>/` 区分评论，留言板使用 `/guestbook/`。加锁文章只在解锁后挂载评论。已有 GitHub Discussions 留言不迁移，也不删除。

## 运行方式

网站继续由 Astro 生成纯静态文件。前端按需加载固定版本的 Twikoo 脚本；评论数据由独立的 Cloudflare Worker 和 D1 保存，计划使用 `https://comments.hatrix.site` 作为后端地址。Worker 使用 Twikoo 官方 Cloudflare 适配器单独部署，不放进网站构建流程。前后端版本保持一致。

评论组件输出稳定的容器、当前 pathname 与加载状态。没有后端配置、脚本加载失败或初始化失败时，显示具体状态；文章正文和页面导航不受影响。Astro 客户端导航后按新页面 pathname 重新挂载；加锁正文解锁后再挂载。无 JavaScript 时保留说明。

## 界面

留言板保留现有半透明机壳、信号环和窄屏布局。Twikoo 直接渲染在页面 DOM 中，表单与留言列表使用站点深色材质、操作金、链接青和铜色边线；按钮、输入框、禁用状态与本站光标一致。文章页评论保持适合阅读的深色底。交互反馈短促，减少动态效果时直接呈现状态。

## 安全与数据

前端脚本固定到 Twikoo 2.0.13 并校验 SRI。CSP 只放行该脚本和实际 Worker 源，不保留 Giscus 的脚本、样式或 iframe 许可。后端密钥、管理员密码和 D1 标识不写入网站代码或构建产物。首次管理员密码由站长在 Twikoo 管理界面设置。

## 验收

本地核对留言板、公开文章、加锁文章、客户端导航和无 JavaScript 状态；桌面与手机都能使用表单，评论区不出现横向溢出。类型检查、相关测试、生产构建、构建产物 CSP/资源审计通过。Worker、D1 与自定义域名部署后，再用真实后端验证读取和发表一条测试留言。
