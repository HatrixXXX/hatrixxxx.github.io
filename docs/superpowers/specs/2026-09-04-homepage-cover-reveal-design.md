# 首页全屏封面与揭开切换设计

## 目标

首页改为单屏封面。页面只显示全屏背景、右上导航、居中的站名与打字文案，以及底部的右向入口箭头。点击箭头或向左拖动页面后进入博客总览页，首页向左滑走，博客页从下层显出。

视觉参数参考 `https://no5-aaron-wu.github.io/` 的首屏，但不复制其源码、文案或个人素材。背景只使用本站的 `public/images/cover.png`。

## 页面边界

首页保留：

- 主导航及现有二级菜单；
- 搜索按钮和搜索弹层；
- 日夜模式按钮与现有主题切换动画；
- `Hatrixの窝` 标题；
- `轻松即单纯，速成即精准` 打字文案；
- 指向 `/blog/` 的右向浮动箭头；
- 鼠标拖动和触摸左滑入口。

首页不渲染：

- 顶部头像和 `Hatrix` 品牌文字；
- 原有博客入口卡片；
- 页脚；
- CursorTrail 画布及运行时；
- Sakana 千束、泷奈节点及运行时；
- 向下滚动提示或首屏之外的内容。

其他页面保持现有布局、品牌、页脚、CursorTrail 和 Sakana，不改变文章 URL、内容模型或搜索逻辑。

## 结构

`BaseLayout.astro` 增加显式首页模式。首页模式负责：

- 给 `html` 和 `body` 增加稳定的首页标记；
- 将无品牌状态传给 `SiteHeader`；
- 不渲染页脚、Sakana 和 CursorTrail；
- 保留 SearchOverlay 与 ThemeTransition；
- 加载首页交互脚本。

`SiteHeader.astro` 继续复用现有导航、搜索、主题和移动菜单，只增加无品牌状态。桌面端全部控件靠右；移动端保留搜索、主题和菜单按钮。非首页仍按原样显示品牌。

`index.astro` 不再使用 `HeroBanner` 和旧入口卡片，改为一个固定在视口内的首页舞台。背景层、遮罩层、文字层和入口箭头都放在这个舞台中。

## 视觉参数

首页使用参考站实测得到的主要参数：

- 全局字体栈：`-apple-system, BlinkMacSystemFont, "IBM Plex Mono", "Microsoft YaHei", sans-serif`；
- 背景：`/images/cover.png`，居中、`cover`、不重复；
- 遮罩：纯黑 `30%`；
- 文本组顶部：视口高度的 `43%`；
- 桌面标题：`2.85rem`、`700`、`1.5` 行高；
- 桌面副标题：`1.72rem`、`400`、`1.5` 行高；
- 手机标题：`1.85rem`；
- 手机副标题：`1.15rem`；
- 标题颜色：`#fff`；
- 副标题和导航颜色：`#eee`；
- 标题阴影：`2px 2px 4px rgb(0 0 0 / 15%)`；
- 导航阴影：`1px 1px 2px rgb(0 0 0 / 30%)`；
- 顶栏高度：`60px`；
- 顶栏水平留白：桌面 `36px`，移动端 `16px`；
- 桌面导航字号约 `1.014rem`。

背景图片作为页面内容资源加入 Git。首页预加载这张图，避免首屏先显示纯色。

## 打字文案

打字效果使用本站脚本实现，不增加 Typed.js 依赖。时序与参考站一致：

- 开始延迟 `300ms`；
- 输入间隔 `150ms`；
- 完整文字停留 `700ms`；
- 回删间隔 `50ms`；
- 循环播放；
- 光标显示为 `|`，以 `700ms` 周期闪烁。

完整文案保留在无障碍名称中，动态字符标记为 `aria-hidden`，避免读屏器反复朗读。页面隐藏或离开首页时清理计时器；Astro 客户端导航回到首页时重新初始化，不能重复创建循环。

当系统启用减少动态效果时，直接显示完整文案和静态竖线，不播放输入、回删和闪烁。

## 固定视口与缩放

首页舞台使用 `position: fixed; inset: 0` 和 `100dvh`。首页标记同时把 `html`、`body` 的宽高限制在当前视口，并设置 `overflow: hidden`、`overscroll-behavior: none`。

这不是单纯隐藏滚动条。实现必须保证：

- `scrollWidth` 不大于 `clientWidth`；
- `scrollHeight` 不大于 `clientHeight`；
- `window.scrollTo(0, 9999)` 后 `scrollY` 仍为 `0`；
- 缩放导致 CSS 视口变窄或变矮时，导航切换到移动布局，页面仍不产生纵向滚动；
- 搜索弹层和主题动画使用 fixed/top-layer，不参与首页文档高度。

## 导航

桌面导航整体位于右上角，顺序为主导航、搜索按钮、日夜模式按钮。主导航与操作按钮之间保留小间距。左上角不留头像或站名占位。

移动端只显示搜索、主题和菜单按钮；展开后的菜单沿用现有可访问性、键盘和二级菜单逻辑。首页导航始终使用白色文字与透明背景，不能因浅色主题切换成深色字。搜索和主题按钮继续使用现有 `aria-label` 与脚本。

## 博客预取

首页不嵌入 iframe，也不复制博客列表 DOM。预加载分两级：

1. 首页稳定后，在浏览器空闲时预取 `/blog/`；
2. 指针进入箭头、开始左拖或获得键盘焦点时再次确认预取。

预取只优化时延，不是导航正确性的前提。预取失败、网络变慢或缓存被清理时，箭头和拖动仍调用 Astro 客户端路由完成导航。不能因为预取失败锁死手势或留在半拖动状态。

## 箭头与拖动

入口位于底部中央，使用站内 SVG 右向箭头，不引入 Font Awesome。图标尺寸 `30px`，点击区域至少 `44px × 44px`。箭头以 `1.5s` 周期左右往返，颜色和阴影与导航一致。

首页背景区域支持 Pointer Events：

- 只接受主按键；
- 导航、按钮、链接、搜索弹层等交互元素不启动拖动；
- 指针按下后捕获 pointer，页面只跟随负向水平位移；
- 竖向移动明显大于横向移动时取消手势；
- 拖动距离达到视口宽度的 `16%`，或向左速度达到 `0.7px/ms` 且距离至少 `48px` 时提交；
- 未达到阈值时，以 `320ms` 缓动回到原位；
- 提交后禁用重复触发，继续完成向左揭开动画并进入 `/blog/`；
- Pointer Events 同时覆盖鼠标拖动和触摸左滑。

拖动期间只修改 `transform: translate3d(...)`，不触发布局计算。拖动层使用 pointer capture，`pointercancel`、窗口失焦和路由离开都能复位。

减少动态效果模式仍识别向左手势，但达到阈值后直接进入博客页，不做跟手位移、回弹或持续动画。

## 揭开动画

点击箭头、点击首页顶部的博客入口或提交左拖时，统一使用首页到 `/blog/` 的揭开动画：

- 新博客页作为静止的下层；
- 旧首页从当前拖动位置继续向左移出；
- 不对新页面做横向位移或淡入；
- 时长 `620ms`；
- 缓动 `cubic-bezier(0.76, 0, 0.24, 1)`；
- 只动画 `transform`，避免主线程逐帧改样式；
- 动画结束后清除临时属性和内联位移。

实现复用 Astro ClientRouter 和原生 View Transitions。入口在导航前预取博客页；原生 View Transitions 不可用时使用 Astro 的 fallback，最终退化为直接切换。减少动态效果时禁用揭开动画。

从首页进入其他路由不强制使用揭开动画。浏览器后退返回首页时使用普通路由切换，避免把手势语义倒放。

## 测试

Playwright 先固定首页契约：

- 背景引用 `/images/cover.png`，资源返回 `200`；
- 标题、副标题、竖线光标和右向箭头存在；
- 首页没有品牌、旧卡片、页脚、Sakana 和 CursorTrail；
- 导航、搜索和主题按钮位于右上控件组；
- 点击箭头进入 `/blog/`；
- 短拖动回弹，长拖动和快速左甩进入 `/blog/`；
- 交互控件上的拖动不触发导航；
- 提交手势时存在揭开动画，完成后没有残留变换；
- 减少动态效果下直接显示完整文案并取消动画；
- `1440×900`、`1152×720`、`960×600`、`720×450`、`768×1024`、`390×844` 和 `360×640` 均无横纵滚动；
- 普通页面仍显示品牌、页脚、Sakana 和 CursorTrail。

原先把首页当作 Sakana 或 CursorTrail 正向样例的测试迁到普通页面，不削弱原有行为覆盖。视觉测试只更新首页的桌面、平板和手机三张基线；其余基线保持不变。

最终执行单元测试、Astro check、图片检查、生产构建、保护内容审计、站点检查和 Playwright。浏览器手工检查桌面、移动端、主题切换、搜索、点击揭开和鼠标拖动。
