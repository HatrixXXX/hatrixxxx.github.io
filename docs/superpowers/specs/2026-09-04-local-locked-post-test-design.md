# 本地加锁文章测试设计

## 目标

在不改线上内容的前提下，为本地开发准备管理员 key 配置和一篇可实际打开的加锁文章。测试完成前不提交或推送私有内容仓库。

## 文件

- 项目根目录新增 `.env.local`，只保留说明和空的 `HATRIX_ADMIN_KEY=`，由用户自行填写。该文件继续由 `.gitignore` 排除。
- `.private-content/posts/` 新增 `2026-09-04-加锁功能测试.md`。文章使用本地默认封面，类型为“技术笔记”，并设置 `draft: false`、`locked: true`。

测试文章使用稳定路径 `/posts/加锁功能测试/`，正文只说明页面用于验证加锁、解锁和会话恢复，不写入 key 或其他敏感信息。

## 本地行为

文章加入后，本地已发布文章数暂时从 40 变为 41，并出现在博客列表与搜索结果中。因为它只留在未提交的私有内容仓库，线上站点不会变化。

空的 `HATRIX_ADMIN_KEY` 不能生成加锁页面。用户填写与 GitHub Actions Secret 相同的值并重启开发服务器后，Astro 才会读取该 key。打开测试文章时只显示解锁界面；输入正确 key 后显示正文。

## 验证

- `.env.local` 存在，并继续被 Git 忽略。
- 测试文章通过现有内容 schema，且 `legacySlug`、`locked` 和 `draft` 值符合上述约定。
- 填写 key 并重启预览后，`/posts/加锁功能测试/` 返回 200，错误 key 不显示正文，正确 key 可以解锁。
- 私有内容仓库保持未提交状态，不 push 测试文章。

现有全量构建检查固定要求 40 篇线上文章，因此本地测试文章存在期间不把 41 篇内容的链接数量写回公共仓库。删除测试文章后，全量门禁恢复原来的 40 篇基线。
