# 导航与内容入口改造

## 目标

主导航改为“首页、博客文章、作品橱窗、关于我、留言板”。“博客文章”和“关于我”带小号倒三角，桌面端只展开当前悬浮或聚焦的二级菜单。

这次同时补齐所有导航目标，避免菜单链接指向 404：

- `/blog/` 展示全部文章。
- `/blog/tech-notes/`、`/blog/troubleshooting/`、`/blog/life/`、`/blog/recommendations/`、`/blog/essays/` 分别展示技术笔记、踩坑记录、生活动态、好物推荐、随笔杂谈。
- `/projects/` 继续承载作品橱窗。
- `/about/` 保留个人简介；九个子项使用 `/about/<section>/` 独立路径。
- `/guestbook/` 使用现有 Giscus 配置保存留言，pathname 映射保证留言板和文章评论互不混用。

原有 `/posts/<legacySlug>/`、首页文章流、归档、搜索和 Giscus 文章映射不变。

## 方案选择

### 采用：CSS 主导的嵌套导航和静态内容入口

桌面二级菜单通过 `:hover` 与 `:focus-within` 控制，链接仍是普通 `<a>`。键盘用户聚焦父项或子项时也能看到菜单，不依赖 JavaScript 才能访问链接。移动端沿用汉堡菜单，父项和缩进后的子项在展开区内直接可见，避免在小屏幕里再套一层难以操作的悬浮菜单。

文章类型和关于子页使用集中配置生成链接与静态路径。页面仍由 Astro 构建为纯 HTML。

### 未采用：JavaScript 控制两套弹出菜单

脚本方案可以处理点击切换和 Escape 关闭，但会增加焦点恢复、互斥状态、客户端换页重置和无 JavaScript 降级逻辑。当前需求只有悬浮展开，用 CSS 更直接。

### 未采用：只改导航文字，链接复用首页锚点

这种改法代码最少，但五种文章类型、九个关于页面和留言板都没有独立地址，不能满足内容后续逐步补全的要求。

## 导航结构

`SiteHeader.astro` 保留品牌、搜索、主题切换和当前 768 px 折叠断点，只替换导航数据和列表结构。

桌面一级项顺序如下：

1. 首页 → `/`
2. 博客文章 → `/blog/`
3. 作品橱窗 → `/projects/`
4. 关于我 → `/about/`
5. 留言板 → `/guestbook/`

“博客文章”和“关于我”的文字本身仍可点击。倒三角只是层级提示，不单独占用一个交互目标。二级菜单与父项之间不留会导致 hover 中断的空隙；两个菜单互不重叠，悬浮在哪个父项上就只显示对应菜单。

桌面菜单默认隐藏，父级 `li:hover` 或 `li:focus-within` 时显示。移动菜单打开后显示完整层级，子项缩进并降低字号或颜色层级，但每个链接仍满足 44 px 触控高度。当前页面通过 `aria-current="page"` 标记。

## 文章类型

文章 schema 新增必填 `type` 字段，只接受以下五个值：

- 技术笔记
- 踩坑记录
- 生活动态
- 好物推荐
- 随笔杂谈

这不是旧的技术领域分类。页面不恢复标签、分类徽章、分类面包屑或搜索 taxonomy 字段；`type` 只用于五个文章入口的筛选。

现有 40 篇文章按主要阅读目的分配：

- 技术笔记 37 篇：除下列三篇外的现有文章。
- 踩坑记录 1 篇：`博客搭建`。
- 好物推荐 2 篇：`工具箱`、`杂货铺`。
- 生活动态 0 篇。
- 随笔杂谈 0 篇。

空类型页显示明确的空状态，不填演示文章。全部文章页和非空类型页按发布时间倒序复用现有文章卡片。

## 关于我

九个子项使用稳定的英文路径：

| 菜单文字 | 路径 |
| --- | --- |
| 我的爱好 | `/about/hobbies/` |
| 我的研究 | `/about/research/` |
| 我爱看的 | `/about/reading/` |
| 我爱玩的 | `/about/games/` |
| 我的相簿 | `/about/albums/` |
| 我的装备 | `/about/gear/` |
| 我的工具 | `/about/tools/` |
| 我的书签 | `/about/bookmarks/` |
| 我的友链 | `/about/friends/` |

这些地址由一个静态动态路由生成，每个地址都有自己的页面标题、Hero 和空状态。后续有内容时可以逐项替换，不需要改导航路径。

## 留言板

`/guestbook/` 使用普通页面布局、Hero 和 `GiscusComments`。Giscus 仍使用 `SITE.giscus` 中的仓库、分类、主题和 pathname 映射；组件允许页面把标题从“评论”改为“留言”，文章页继续显示“评论”。脚本加载失败时保留现有错误提示，页面其余内容照常显示。

## 测试与构建

实施按以下顺序验证：

- 单元测试先约束五种类型、40 篇文章的显式 `type` 字段和类型路径。
- E2E 测试覆盖五个一级项、两个互斥的桌面二级菜单、键盘聚焦、移动端完整层级、五个类型页、九个关于子页和留言板 Giscus 配置。
- 无 JavaScript 桌面测试继续确认所有目标是可访问的普通链接。
- 更新受公共 Header 影响的 Windows 视觉基线。
- 运行单元测试、Astro 类型检查、图片预检、构建、站内链接检查和 Playwright；根据实际构建结果更新固定站内链接计数。

## 边界

- 保持纯静态输出，不增加服务端接口或数据库。
- 不修改文章正文、旧文章 URL、Giscus 文章 pathname、作品数据和歌单数据。
- 不恢复 `/categories/**`、`/tags/**` 或旧 taxonomy 展示。
- 关于子页保持空状态，用户补充内容前不生成虚构资料。
