# Astro 个人博客重构设计

日期：2026-09-01

## 1. 目标

将现有 Jekyll/Chirpy 博客重写为 Astro 静态站点，继续使用 GitHub Pages、`hatrix.site`、现有 DNS、ICP备案和 Giscus 评论配置。

新站参考 [linn-ylz.com](https://linn-ylz.com/) 的页面结构和视觉语言：全屏题图、波浪分隔、深色背景、粉色强调色、交错图文卡片、作者侧栏、文章题图、归档、分类、标签和正文目录。实现代码、站点文案、图片、头像和品牌信息均使用本项目自己的内容，不复制参考站源码或作者个人资产。

本次重构先解决博客结构、内容迁移和基础交互。音乐播放器与作品页只搭好可扩展的空壳。3D 场景留到后续功能迭代。

## 2. 迁移前现状与最终校准

- 现有技术栈为 Jekyll、Chirpy 7.2.4、Ruby 和一套主题资产构建脚本。
- 仓库有 40 篇 Markdown 文章，URL 形式为 `/posts/<文章名>/`。
- 文章包含数学公式、Mermaid、代码块和大量图片。
- 文章没有稳定的分类和标签元数据，也没有作品集合。
- 非标准 `_draft` 目录中有两篇未发布草稿。它们不会生成页面，但清理旧站前要迁入 `src/drafts/` 保存。
- 最终迁移内容共有 254 个去重后的外部图片 URL，全部来自 `cdn.jsdelivr.net/gh/HatrixXXX/Hatrix-s-Blog-Image/`。
- 图床仓库约 280 MB，共 1020 个文件；不能整仓复制进博客。
- 迁移前自定义域名写在根目录 `CNAME`；Astro 站以 `public/CNAME` 为唯一来源，构建后复制到 `dist/CNAME`。
- 现有 Bing 站点验证码继续写入页面 metadata。
- Giscus 使用 pathname 映射。旧文章 URL 发生变化会切断现有讨论串。
- 迁移启动时对照仓库位于 `master`，Astro 重构在独立 worktree 中完成。

## 3. 范围

### 3.1 首版包含

- Astro 静态输出和 GitHub Pages 部署。
- 首页、文章页、归档、分类、标签、作品、关于和 404 页面。
- 40 篇文章迁移，正文不改写。
- 两篇未发布草稿原样保存，不进入 Content Collection。
- 文章分类、标签和系列元数据补全。
- 数学公式、Mermaid、代码高亮、图片灯箱和文章目录。
- Giscus 评论、RSS、站点地图、SEO 元数据和社交分享信息。
- 桌面与移动端导航、全局搜索、主题切换和页面转场。
- 音乐播放器组件及空歌单状态。
- 作品集合、作品页布局及空状态。
- 图片优化、旧 URL 检查、视觉回归和性能检查。

### 3.2 首版不包含

- 具体歌曲和音频资源。
- 具体作品条目。
- Three.js、Babylon.js 或其他 3D 场景。
- 文件上传、文件下载中心、对象存储和访客文件管理。
- 服务端账号、数据库或管理后台。
- 全站最新评论。文章内部继续使用 Giscus。
- 对旧文章正文进行润色或改写。

## 4. 技术方案

### 4.1 基础技术栈

- Astro，使用纯静态输出。
- TypeScript 严格模式。
- pnpm 和锁文件。
- Astro Content Collections 管理文章和作品。
- Astro View Transitions 管理页面切换，并通过 `transition:persist` 保留播放器状态。
- 样式以 Astro scoped CSS 和全局 CSS 变量为主。Tailwind、SCSS、jQuery 和前端组件框架没有禁用；只有出现明确收益或现成依赖时才引入。
- 普通交互优先使用原生 TypeScript。后续 3D 页面可独立使用 Three.js、Babylon.js、React Three Fiber 或其他客户端方案。

### 4.2 部署边界

GitHub Pages 只托管构建后的 HTML、CSS、JavaScript 和静态资源。首版没有需要服务器处理的功能。未来如果增加动态接口，使用独立 API 或对象存储，不把密钥放进浏览器端代码。

## 5. 页面与路由

### 5.1 首页 `/`

- 顶部透明导航，滚动后切换背景和阴影。
- 全屏题图，显示站名、标语和滚动提示。
- 波浪形分隔进入正文区。
- 文章卡片左右交错排列，包含头图、标题、摘要、日期、阅读时长、分类和继续阅读按钮。
- 右侧作者栏显示头像、简介、文章/分类/标签数量、社交链接和站内菜单。
- 文章分页。
- 页脚显示随机文章、最近更新和版权信息。

### 5.2 文章页 `/posts/[slug]/`

- 保留旧路径 `/posts/<文章名>/`，中文 slug 使用与现站一致的 URL 编码结果。
- 题图区域显示文章标题、发布日期、修改时间、字数和阅读时长。
- 正文区包含面包屑、Markdown 内容、代码块、数学公式、Mermaid 和图片灯箱。
- 桌面端右侧显示悬浮目录；移动端使用折叠目录。
- 底部显示标签、版权说明、上下篇和 Giscus。

### 5.3 内容索引

- `/archives/`：按年、月汇总。
- `/categories/`：显示层级分类和数量。
- `/categories/[...slug]/`：显示分类内文章。
- `/tags/`：显示标签云。
- `/tags/[tag]/`：显示标签内文章。

### 5.4 作品与关于

- `/projects/`：保留标题、介绍、筛选区、卡片网格和空状态。首版没有作品条目。
- `/about/`：显示个人介绍、头像和社交链接。内容取自现有站点配置，后续可单独编辑。
- `/404.html`：使用同一套题图、字体和色彩。

## 6. 组件边界

- `BaseLayout`：HTML 骨架、SEO、全局样式、View Transitions 和公共脚本。
- `SiteHeader`：桌面导航、移动端菜单、搜索和主题切换。
- `HeroBanner`：首页及文章页题图。
- `WaveDivider`：题图与正文之间的波浪过渡。
- `PostCard`、`PostList`、`Pagination`：文章摘要列表。
- `ProfileSidebar`：作者资料、统计和社交链接。
- `PostMeta`、`Breadcrumbs`、`PostContent`、`TableOfContents`：文章页主体。
- `SearchOverlay`：基于构建期索引的本地搜索。
- `MusicPlayer`：播放器 UI、播放状态和空歌单。
- `ProjectGrid`：作品列表和空状态。
- `SiteFooter`：随机文章、最近更新和版权。

组件只接收完成渲染所需的数据，不直接读取无关集合。文章查询、分页、分类和标签聚合放在独立的构建期工具函数中。

## 7. 内容模型

### 7.1 文章

每篇文章包含以下字段：

- `title`
- `description`
- `pubDate`
- `updatedDate`，可选
- `cover`
- `category`
- `tags`
- `series`，可选
- `seriesOrder`，可选
- `draft`
- `math`
- `mermaid`
- `legacySlug`

构建时检查字段类型、日期、重复 slug 和系列顺序。正文仍为 Markdown。

### 7.2 初始分类

现有文章按正文主题归入以下一级分类：

- FPGA 与数字系统
- 嵌入式与硬件
- AI 与图形计算
- 软件工程与工具
- 数学与基础
- 随笔与资源

标签使用具体技术名称，例如 Verilog、Vivado、AXI、STM32、CUDA、3DGS、Docker 和 Git。编号文章同时补充系列名和顺序。分类和标签只改变索引方式，不改正文。

### 7.3 作品

作品集合允许为空。预留字段包括标题、简介、状态、头图、技术栈、链接、是否精选和排序值。首版页面显示空状态，不放示例假数据。

### 7.4 音乐

播放列表使用有类型约束的独立数据文件。首版数组为空。播放器在空列表时显示“歌单待添加”，不请求音频资源。

## 8. 数据流

1. Astro 在构建时读取文章和作品集合。
2. 内容校验先于页面生成；无效元数据会让构建失败并指出文件路径。
3. 构建期工具生成文章排序、分页、归档、分类、标签、系列、随机文章和搜索索引。
4. 页面输出静态 HTML。搜索、菜单、主题、灯箱和播放器在浏览器端按需运行。
5. Giscus 在文章页加载，不阻塞正文首屏。

没有 JavaScript 时，文章、分页、归档、分类、标签和普通导航仍然可用。搜索、播放器、灯箱和 Mermaid 交互可以退化，不影响正文阅读。

## 9. 图片方案

- 不复制整个图床仓库。
- `pnpm build` 先检查 254 个被引用的 URL，并生成不提交 Git 的检查报告。
- 在 Astro 中授权现有 jsDelivr 域名。文章列表题图由 Astro 图片管线和 Sharp 生成响应式 WebP，并复用 `.astro/` 缓存。
- 正文远程图片预检后保留 jsDelivr 地址，输出 `loading="lazy"` 和 `decoding="async"`，避免把 254 张正文资源全部纳入构建转换。
- GIF 和 SVG 保持原格式，避免动画或矢量信息丢失。
- 失效图片替换为本地占位图，并保留原始 alt 文本和源 URL 供排查。
- GitHub Actions 缓存 Astro 图片处理目录。
- 当前实现只转换题图，正文图片继续使用 jsDelivr；构建门禁仍要求总时长少于 8 分钟。

## 10. 交互与性能

- 播放器通过 View Transitions 保持组件和状态，不因站内跳转重置。
- 搜索索引按标题、摘要、分类、标签和正文摘要生成。
- 主题设置、播放器音量和界面状态写入 `localStorage`。
- 页面转场尊重 `prefers-reduced-motion`。
- 3D 依赖不进入首版依赖树，也不出现在普通页面产物中。
- 首页客户端 JavaScript 的 gzip 体积目标不超过 160 KB，不计 Giscus iframe。
- 本地 Lighthouse 目标为桌面性能不低于 90、移动端不低于 80，CLS 低于 0.1。

浏览器禁止有声自动播放时，播放器停在待播放状态，不反复弹出提示或重试。

## 11. 错误处理

- 缺少文章头图时使用站点默认图。
- 重复 slug、无效日期、未知分类和系列顺序冲突会阻止构建。
- 失效外链图片进入检查报告，并使用本地占位图。
- 空作品集合和空播放列表显示明确空状态。
- 运行期脚本失败时保留静态正文和导航。
- 未匹配路由进入自定义 404 页面。
- Giscus 加载失败时显示评论暂不可用，不影响文章内容。

## 12. 旧站清理

清理发生在 Astro 构建、链接检查和视觉验证通过之后。

保留：

- Git 历史和远程配置
- `public/CNAME`
- 迁移后的文章
- `src/drafts/` 中保留的两篇未发布草稿
- 有效头像、favicon 和个人图片
- 社交链接、站点验证信息和 Giscus 参数
- 历史许可与来源通过 Git 历史追溯；根目录不声明新站源码或文章的开源许可

删除或替换：

- `Gemfile`、Ruby/Jekyll 配置与缓存规则
- `_layouts`、`_includes`、`_sass`、`_javascript`、`_plugins`、主题 `_data` 和 `_tabs`
- Chirpy 专用 JavaScript、CSS、PurgeCSS 和 Rollup 配置
- Jekyll 专用工具脚本、开发容器配置和工作流
- 已迁移的 `_posts` 副本
- 重复、失效或只服务旧主题的图片与模板资源

所有删除都提交到功能分支，可从 Git 历史恢复。构建产物、缓存和 `.superpowers/` 不进入 Git。

## 13. 开发方式

- 重构期间让对照仓库保持可运行，用于核对内容和页面。
- Astro 代码在 `feature/astro-blog-rebuild` worktree 中完成；旧主题只保留到新站通过构建、链接和视觉验证。
- 本分支不推送、不部署，也不改远端 Pages 设置。后续是否合并和部署由用户另行决定。
