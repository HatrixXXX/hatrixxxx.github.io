# 首页首屏原子呈现与角色资源优化设计

## 背景

首页人物已经从单张图片改成 29 张骨骼分块图，但加载逻辑仍按单图处理。`page-loader.ts` 只等待人物区域中的第一张图片和背景图，随后把进度设为 100%。其余分块继续加载和解码，因此加载遮罩消失后还能看到人物逐块补齐。

播放器在首页中是音乐面板的兄弟节点。服务端首帧只有 `position: absolute` 和尺寸，位置与透视矩阵由客户端脚本稍后从空的音乐面板复制。播放器的 `transform` 过渡会把这次布局校正显示成从左上角滑向左下角。

本次同时恢复首页的金句卡片和可见的 `Hatrix` 名称。等级圆环保留，名称移到圆环右侧。

## 目标

- 人物 29 个分块全部加载并解码后，整个人物一次出现。
- 人物准备完成前，骨骼动画暂停，不显示任何局部分块。
- 播放器首次可见时已经位于首页左下角的最终透视位置，不播放位置校正动画。
- 首页加载遮罩等待背景、人物和播放器。条件未结束时进度不能显示 100%。
- 任一人物分块失败或人物等待超过 8 秒时，结束加载遮罩，但该次访问不显示残缺人物。
- 恢复金句卡片及原有切换行为。
- 恢复可见的 `Hatrix` 名称，放在等级圆环右侧；等级圆环的位置和功能不变。
- 将人物分块裁到非透明内容边界，改成无损透明 WebP，并用偏移数据恢复原来的骨骼坐标。
- 保留 Astro 客户端导航、播放器 `transition:persist`、无 JavaScript 降级和减少动态效果设置。

## 不做的事

- 不修改人物造型、骨骼层级、动作幅度或图片内容。
- 不把人物重新合成单图，也不改成 Canvas、SVG 或 WebGL。
- 不改变右侧面板、等级算法、播放器功能和其他页面布局。
- 不借这次改动清理 `character-idle.ts` 中现有但失效的旧视差选择器。

## 资源现状与目标

当前 29 张 PNG 均为 `1024×1536` 完整画布，总文件大小约 6.74 MiB。按 RGBA 展开后的理论内存约 174 MiB。旧单张 PNG 为 1.87 MiB，旧版 Astro WebP 的同等参数估算约 0.24 MiB。

对每张分块图按 alpha 非零区域裁边后，使用 Sharp 转成无损透明 WebP。试算结果如下：

- 总文件大小约 1.11 MiB；验收上限为 1.25 MiB。
- 理论 RGBA 解码内存约 19.63 MiB；验收上限为 22 MiB。
- 请求数仍为 29，不新增运行时打包器或图片依赖。

每个 WebP 记录原画布中的 `x`、`y`、`width` 和 `height`。组件继续保留现有骨骼 DOM 层级，图片改用裁切后的尺寸和绝对偏移。转换后删除 `public/character-parts/*.png`，保留骨骼 JSON 和生成后的 WebP。偏移清单放在有类型约束的源码数据文件中，供组件和测试共同使用。

## 人物就绪状态

`CharacterIdle` 最外层使用 `data-character-state`：

- `loading`：默认状态。整体不可见，骨骼动画暂停。
- `ready`：29 张图片全部成功加载并完成 `decode()`。整体立即可见，骨骼动画开始。
- `error`：任一图片失败，或等待超过 8 秒。整体保持隐藏。

初始化时把尚未请求的 lazy 图片提升为 eager，然后逐张等待 `load` 或已有的 `complete` 状态；加载成功后还要等待 `decode()`。状态结束时派发人物就绪事件。事件用于通知加载器，属性用于处理监听建立前已经完成的情况。

已访问过首页时，全局加载遮罩仍按现有规则跳过，但人物自身的状态机继续执行，因此不会出现逐块加载。无 JavaScript 时用 `<noscript>` 样式直接显示图片，避免人物永久隐藏。

人物从 `loading` 切到 `ready` 时不做淡入、位移或分块 stagger。`prefers-reduced-motion: reduce` 使用同一加载判断，但骨骼动画保持关闭。

## 播放器位置状态

播放器增加 `data-layout-state`：

- 首页服务端首帧为 `pending`，CSS 使用 `visibility: hidden` 并关闭播放器本体的 transform 过渡。
- dock 模式为 `ready`，继续使用左侧固定布局。
- 客户端同步首页模式时，先保持 `pending`，再写入音乐占位面板的 `left`、`top`、`transform` 和 `transform-origin`。浏览器提交最终几何后切换为 `ready`。

首次显示没有额外淡入。`ready` 的第一帧就是左下角最终位置。播放器已有的展开、折叠、唱片和音臂动画不变。

跨页导航继续复用同一个播放器和 Audio。进入首页前把持久化节点标为 `pending`，完成首页几何同步后再设为 `ready`；离开首页时清除首页内联几何并恢复 dock 状态。布局同步和事件绑定分开，重复导航不能重建 Audio 或重复绑定监听器。

## 加载遮罩与进度

首页加载遮罩等待三个条件：

1. 工坊背景加载完成或明确失败。
2. 人物状态结束为 `ready` 或 `error`。
3. 播放器布局为 `ready`。

进度仍采用现有的平滑假进度，但最高停在 85%。三个条件结束后才设为 100% 并开始遮罩淡出。人物失败时可以结束加载，但人物保持隐藏。通用 8 秒兜底继续保留，兜底触发时把仍在 `loading` 的人物标记为 `error`，防止遮罩消失后人物又突然出现。

减少动态效果时，加载条件和进度语义不变；LOADING 脉冲关闭，遮罩按现有 0.1 秒快速淡出。

## 首页身份和金句

等级圆环继续使用当前 `identity` 面板及现有坐标。新增独立的名称面板，位于等级圆环右侧，设计画布中至少留 12px 间距。名称沿用旧版 `Hatrix` 的等宽字设计，不覆盖等级圆环，也不遮挡人物头部和面部。

恢复旧版金句面板及 `HOME_QUOTES` 数据。行为保持原设计：

- 每 15 秒自动切换。
- 双击、Enter 或空格立即切换。
- 保留暂停与恢复控制。
- `prefers-reduced-motion: reduce` 下默认暂停自动切换。
- Astro 客户端导航返回首页时只建立一组定时器和监听器。

金句面板使用旧版左侧位置，位于身份区与播放器之间，不改变播放器、友链和留言板的最终几何。

## 测试

### 单元和结构测试

- 29 个资源清单项各有 WebP 文件、非负偏移和正尺寸，且全部落在 `1024×1536` 原画布内。
- `public/character-parts/` 不再包含人物 PNG。
- WebP 总大小不超过 1.25 MiB，裁切后理论 RGBA 总量不超过 22 MiB。
- 播放器首页同步后，位置状态为 `ready`，内联几何与音乐占位面板一致。
- dock 模式清除首页几何，不重复创建 Audio。
- 首页重新包含可见 `Hatrix` 标题和金句控件。

### 浏览器测试

- 延迟最后一张人物图片时，人物保持隐藏，加载进度不为 100%，遮罩不退出；放行并完成解码后，人物整体出现，随后遮罩结束。
- 图片失败或 8 秒超时时，遮罩结束，人物保持隐藏。
- 首页已在 sessionStorage 中标记为访问过时，不显示加载遮罩，但人物仍保持整体门控。
- 播放器的首个可见边界框与最终边界框一致，首次加载不触发 transform transition。
- 首页与普通页往返后仍只有一个播放器节点，播放状态不丢失。
- 减少动态效果下人物加载门控仍有效，人物和播放器不产生空间入场动画。
- 无 JavaScript 时首页主要入口、名称、金句静态内容和人物仍可见。

桌面、平板和手机各检查一次首页截图。重点检查等级圆环与 `Hatrix` 名称的间距、人物轮廓、金句卡片、播放器位置和竖屏裁切。

## 验收条件

- 冷缓存下不再出现人物逐块补齐。
- 加载遮罩到 100% 时，人物已经完整解码，播放器已经处于最终位置。
- 播放器没有从左上角滑向左下角的首屏过程。
- 29 张裁切 WebP 的位置与原 PNG 合成结果逐像素一致。
- 人物异常不会卡住页面，也不会显示残缺图层。
- 金句卡片和可见的 `Hatrix` 名称恢复，等级圆环保留且不被遮挡。
- 现有单元测试、Astro 检查、生产构建、站点检查和相关 Playwright 套件通过。
