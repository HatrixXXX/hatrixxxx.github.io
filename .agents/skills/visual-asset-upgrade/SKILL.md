# 页面视觉素材升级

用户给出要优化的部位后，完成素材制作、页面接入和验证；不把选图、下载或逐张确认交还给用户。生图使用 Codex 内置 `imagegen`，不能指定 ChatGPT 网页的 Pro 档位。只处理本次指定范围，遵守项目 `AGENTS.md` 与 `DESIGN.md` 的现行约束。

1. **核对现场。** 查看工作区状态、目标页面的组件和样式、现有素材、桌面与手机布局，以及 `DESIGN.md` 对该部位的要求。保留其他会话的未提交改动和用户已选定的素材。按需调用项目级前端设计 skill，不为局部任务加载整套设计资料。
2. **确定最小素材清单。** 为每张图写明用途、前后层关系、内容窗、比例和显示尺寸。静态后壳、内腔、前框可以用图片；真实文字、封面、链接、按钮与交互状态由 Astro/CSS/脚本实时呈现。只有图片能明显改善材质或体积时才生图；规则边框、精确刻度和状态光效优先用 CSS/SVG。桌面与手机若构图不同，分别制作。
3. **留存提示词。** 用页面或组件的稳定英文短名作为 `<目标部位>`，在 `docs/design-references/<目标部位>/prompts.md` 为每件素材写一段可单独执行的完整提示词，一段只生成一张图。说明内容、材质、视角、光向、配色、构图、比例、参考图角色、必须保留的空白/透明区域及禁用元素。引用现有 token 和 `DESIGN.md`，不把网页文字、品牌或第三方参考图的具体造型烘焙进图片。该文件同时记录选用原图、处理方式及运行时路径。
4. **生成和选图。** 调用内置 `imagegen`，每件素材单独生成；需要修改已有位图时也按其编辑流程操作。检查直线、内容窗、受光、可裁切余量和透明度，只对有明确问题的图做定向重试。选用母图保存在同一 `docs/design-references/<目标部位>/` 目录。若本次会话没有内置生图能力，说明阻碍并保留提示词；不擅自改用 ChatGPT 网页脚本或收费 API。
5. **处理和接入。** 用项目已有的 Sharp 做确定性裁切、透明边缘整理、尺寸优化与 WebP 输出，运行时文件放 `public/assets/<目标部位>/`。保持母图与派生图的对应关系；不能把歪斜的接缝、螺钉或刻度任意拉伸。按后壳／实时内容／前景件分层接入现有 Astro 组件，保留原有路径、数据和操作。状态反馈与减少动态效果设置遵守 `AGENTS.md`。
6. **验证并交付。** 运行与改动相称的检查，按项目命令启动或核对本地预览，实际查看桌面和手机画面；改了交互或动效时触发相关状态、键盘/触控路径与减少动态效果。更新 `DESIGN.md` 中已落地的现行规则和素材来源。最终简要报告优化部位、素材与提示词路径、检查结果及未解决的问题。
